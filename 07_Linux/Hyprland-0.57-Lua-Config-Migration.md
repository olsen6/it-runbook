# Hyprland Update Broke the Desktop: Migrating hyprland.conf to Lua

| Field | Details |
|---|---|
| **Type** | Ticket |
| **Category** | Linux / Desktop Environment |
| **Environment** | Custom PC running Arch Linux with Hyprland (Wayland) |
| **Status** | Resolved |
| **Tools** | Hyprland, hyprctl, Waybar, wl-clipboard, bash heredocs |
| **Skills** | Reading release notes, config migration, Linux CLI, troubleshooting my own fix |

## Problem
After an update, Hyprland loaded with a yellow "You're using an autogenerated config!" warning. My taskbar, wallpaper, notifications, theme, and most of my keybinds were gone. I could only open a terminal (SUPER+Q) and the file manager.

## Diagnosis
- The warning mentioned `hyprland.lua`, but my config was `hyprland.conf`.
- `ls ~/.config/hypr/` showed my `hyprland.conf` was still there. Nothing had been deleted.
- Looked up the release: Hyprland 0.57 (Oct 28, 2026) dropped the old `.conf` format and only reads `hyprland.lua` now. There's no converter.
- So Hyprland couldn't find a Lua config, made a blank one, and ignored mine.

## Resolution
1. Got my taskbar back for the moment:
   ```
   waybar > /dev/null 2>&1 & disown
   ```
2. Moved the blank auto-generated file out of the way:
   ```
   mv ~/.config/hypr/hyprland.lua ~/.config/hypr/hyprland.lua.bak
   ```
3. Rewrote my config in Lua by hand, using the auto-generated file to figure out the new syntax. Some examples:

   | Old (`.conf`) | New (`.lua`) |
   |---|---|
   | `monitor = DP-2, 1920x1080@280, 0x0, 1` | `hl.monitor({ output = "DP-2", mode = "1920x1080@280", position = "0x0", scale = 1 })` |
   | `exec-once = waybar` | `hl.on("hyprland.start", function () hl.exec_cmd("waybar") end)` |
   | `bind = $mainMod, Q, exec, kitty` | `hl.bind(mainMod .. " + Q", hl.dsp.exec_cmd("kitty"))` |
   | `bindel = ,XF86AudioRaiseVolume, exec, ...` | `hl.bind("XF86AudioRaiseVolume", hl.dsp.exec_cmd("..."), { locked = true, repeating = true })` |
   | `general { gaps_in = 5 }` | `hl.config({ general = { gaps_in = 5 } })` |

4. Fixed two old keybinds that were using a variable I never defined (`$SUPER_SHIFT`). Now they're SUPER+SHIFT+U for screenshots and SUPER+SHIFT+L to lock.
5. Wrote the new file a section at a time: the first part with `cat > ~/.config/hypr/hyprland.lua << 'EOF'`, the rest with `cat >>`.
6. Checked it and reloaded:
   ```
   head -1 ~/.config/hypr/hyprland.lua
   tail -3 ~/.config/hypr/hyprland.lua
   hyprctl reload
   hyprctl configerrors   # no output = no errors
   ```
7. Logged out and back in so my startup apps (Waybar, hyprpaper, swaync, hypridle) would launch.

## Issues With the Fix Itself
- Pasting the whole config at once got cut off halfway, and the terminal just sat there waiting. Smaller pastes fixed that.
- At one point I copied a command after copying the config, so the file got the command instead of the config. `hyprctl configerrors` caught it right away: `hyprland.lua:1: syntax error near '-'`.

## Lesson
- Read the release notes before big updates. This change was announced ahead of time.
- If something looks "reset," check whether the files are actually gone first. Mine were fine; Hyprland just stopped reading them.
- Run `hyprctl configerrors` before logging out.
- My dotfiles should be in Git so I always have a working copy to go back to.
