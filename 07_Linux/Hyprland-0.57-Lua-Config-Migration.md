# Hyprland Update Broke the Desktop: Migrating hyprland.conf to Lua

| Field | Details |
|---|---|
| **Type** | Ticket |
| **Category** | Linux / Desktop Environment |
| **Environment** | Custom PC running Arch Linux with Hyprland (Wayland) |
| **Status** | Resolved |
| **Tools** | Hyprland, hyprctl, Waybar, wl-clipboard, bash heredocs |
| **Skills** | Reading release notes, config migration, Linux CLI, troubleshooting my own fix |

## Problem
After a system update, Hyprland came up with a yellow "You're using an autogenerated config!" warning. My taskbar, wallpaper, notifications, theme, and most keybinds were gone. Only the default terminal (SUPER+Q) and file manager still opened.

## Diagnosis
- The warning pointed to `~/.config/hypr/hyprland.lua`, but my config has always been `hyprland.conf`.
- `ls ~/.config/hypr/` showed my original `hyprland.conf` was still there, untouched. Nothing was deleted.
- Researched the update: **Hyprland 0.57 (October 28, 2026) dropped the old `.conf` format.** It only reads `hyprland.lua` now, and there's no automatic converter.
- **Root cause:** Hyprland couldn't find a Lua config, so it generated a blank default and ignored mine.

## Resolution
1. Brought the taskbar back for the current session:
   ```
   waybar > /dev/null 2>&1 & disown
   ```
2. Backed up the autogenerated file:
   ```
   mv ~/.config/hypr/hyprland.lua ~/.config/hypr/hyprland.lua.bak
   ```
3. Converted my config to Lua by hand, using the autogenerated file as a syntax reference. Examples:

   | Old (`.conf`) | New (`.lua`) |
   |---|---|
   | `monitor = DP-2, 1920x1080@280, 0x0, 1` | `hl.monitor({ output = "DP-2", mode = "1920x1080@280", position = "0x0", scale = 1 })` |
   | `exec-once = waybar` | `hl.on("hyprland.start", function () hl.exec_cmd("waybar") end)` |
   | `bind = $mainMod, Q, exec, kitty` | `hl.bind(mainMod .. " + Q", hl.dsp.exec_cmd("kitty"))` |
   | `bindel = ,XF86AudioRaiseVolume, exec, ...` | `hl.bind("XF86AudioRaiseVolume", hl.dsp.exec_cmd("..."), { locked = true, repeating = true })` |
   | `general { gaps_in = 5 }` | `hl.config({ general = { gaps_in = 5 } })` |

4. Fixed two old keybinds that used an undefined `$SUPER_SHIFT` variable. They're now SUPER+SHIFT+U (screenshot) and SUPER+SHIFT+L (lock).
5. Wrote the new file in small chunks: the first with `cat > ~/.config/hypr/hyprland.lua << 'EOF'`, the rest with `cat >>`.
6. Verified and reloaded:
   ```
   head -1 ~/.config/hypr/hyprland.lua
   tail -3 ~/.config/hypr/hyprland.lua
   hyprctl reload
   hyprctl configerrors   # no output = no errors
   ```
7. Logged out and back in so the autostart apps (Waybar, hyprpaper, swaync, hypridle) launched.

## Issues With the Fix Itself
- **Pasting the whole config at once got cut off partway**, so the terminal sat waiting for the rest. Splitting it into smaller chunks fixed it.
- **Copying a command overwrote the clipboard** that held the config, so `wl-paste` wrote the command text into the file. `hyprctl configerrors` caught it with `hyprland.lua:1: syntax error near '-'`.

## Lesson
- Read the release notes (and archlinux.org/news) before big updates. A breaking change like this is announced ahead of time.
- When something "resets," check whether your files are actually gone before redoing anything. Mine were fine; the program just stopped reading them.
- Always verify a config with the tool's own checker (`hyprctl configerrors`) before logging out.
- Keep dotfiles in a Git repo so a known-good config is always one command away.
